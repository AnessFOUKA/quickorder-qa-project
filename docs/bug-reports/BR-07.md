### BR-07 — L'API se connecte implicitement à un compte Alice et expose ses commandes à n'importe quel client
- Contexte : l'API utilise une identité fixe pour les utilisateurs non authentifiés, plutôt que d'authentifier la requête par l'utilisateur réel.
- Préconditions : clé API valide (`X-API-Key: quickorder-demo-key`), aucun cookie de session utilisateur ou session d'un autre compte.
- Étapes :
  1. Appeler `GET /api/orders` avec la clé API valide.
  2. Vérifier la réponse JSON.
- Résultat attendu : l'utilisateur ne doit pas pouvoir récupérer les commandes d'un autre client sans être authentifié comme ce client.
- Résultat obtenu : `api_customer()` renvoie `User.query.filter_by(email="alice@example.com")` si l'utilisateur n'est pas connecté ; l'API récupère donc les commandes d'Alice par défaut.
- Preuve : dans `app/routes/api.py`, la fonction `api_customer()` fait un fallback sur `alice@example.com` ; `list_orders()` et `get_order()` filtrent ensuite sur `user_id=api_customer().id` sans vérifier l'identité réelle du client qui appelle l'API.
- Sévérité : Critique
- Priorité : Haute
